# SQLite 作为数据真源的实施计划

## 决策：保留 catalog shard 作为 SQLite 的导出产物

三个 Explore agent 的证据链证明**彻底废弃 catalog shard 代价过高**：
- **validate.py:3282-3286** 硬断言"公开 6 数组必须等于 catalog merge 结果"
- **validate.py:3110-3136** 要求 catalog shard 带 `source_id`/`generated_from`/`transformer_id` 等 provenance 字段
- **test_wikidata_pilot.py** 把 catalog shard 当 ground truth 做 sha256 pin

所以目标数据流是**单向、保留 shard**：

```
SQLite (data/architecture-history.db, 本地真源, gitignored)
   ↓  db.py export（新增子命令）
assets/data/catalog/wikidata-hydration.json (shard, 本地, gitignored) ← SQLite 的导出快照
   ↓  build.py merge_catalog_shards（现有，不改）
assets/data/*.json (8 张线上表, git tracked) + manifest + loader + html token
```

SQLite 成唯一编辑入口；catalog shard 降级为 SQLite 的导出快照。所有 validate/test 闸门自然满足。

## 前置：当前 SQLite schema 的 3 个缺口（db.py agent 证据）

| 缺口 | 证据 | 修复 |
|---|---|---|
| relations 无 payload 兜底列 | db.py:97-108 只有标量列 | 加 `payload TEXT NOT NULL`，存完整 relation dict |
| shard 顶层元数据丢失 | catalog_payload() db.py:57-60 丢弃 generated_from/transformer_version 等 | 保留这些 key；import 时写入 schema_meta |
| work_credits 无显式 ord | db.py:135-144 靠 AUTOINCREMENT id 隐式排序 | 加 `ord INTEGER NOT NULL` 列 |

**无需改**：entities.payload（db.py:208）、claims.payload（db.py:270）、claim_evidence.payload（db.py:286）已是完整原始 dict，含 work.credits[] 和 claim.evidence[] 子数组。

## 实施阶段

### 阶段 0：扩 SQLite schema 补缺口（纯增强）
- `tools/db.py`：relations 表加 payload 列；work_credits 加 ord 列；catalog_payload 保留 shard 元数据；cmd_import 写 schema_meta（generated_from/transformer_version/imported_at）；schema_version 升 "1"→"2"，用 ALTER TABLE ADD COLUMN 安全迁移
- 新增 `tools/test_db.py`：import→export 往返无损测试
- 验证：`db.py import` + `db.py verify` 通过

### 阶段 1：实现 db.py export 子命令（核心）
- `tools/db.py` 加 `cmd_export` + `export_catalog_shard(conn, path)`：
  - entities 表按 source_table 分组读 payload → 4 数组
  - claims 表 payload → claims 数组（已含 evidence[]）
  - relations 表 payload → relations 数组（新 payload 列）
  - schema_meta → shard 顶层元数据
  - 按 id 排序 + `ensure_ascii=False, indent=2, sort_keys=True` 保证确定性
- 子命令：`python3 tools/db.py export [--shard PATH] [--no-public]`，默认写 shard + 触发 build.py 出公开 JSON

### 阶段 2：往返闭环 + 真源切换
- 跑 `db.py export --no-public` → 新 shard 与原 shard **逐字节 diff**（零差异=无损证明）
- 若有差异，定位字段级修复，重跑直到零差异
- 往返测试固化到 test_db.py
- AGENTS.md 更新数据流文档

### 阶段 3：全链验证 + commit
- `db.py export`（含 build）后 4 个闸门全 green
- `git diff` 显示 8 张线上 JSON + manifest + loader + index.html **零变化**（架构切换零回归证明）
- 分批 commit：
  1. `feat(arch-history): extend SQLite schema for lossless export`
  2. `feat(arch-history): add db.py export subcommand (SQLite → shard → public JSON)`
  3. `docs(arch-history): document SQLite as source of truth`
  4. `test(arch-history): add SQLite roundtrip lossless tests`

## 关键风险与缓解

| 风险 | 缓解 |
|---|---|
| export shard 与原 shard 字节不一致 | 阶段 2 往返测试是硬闸门；不一致则字段级修复 |
| schema 迁移破坏现有 45MB 库 | ALTER TABLE ADD COLUMN 原生安全；保留 `rm db && db.py import` 重建路径 |
