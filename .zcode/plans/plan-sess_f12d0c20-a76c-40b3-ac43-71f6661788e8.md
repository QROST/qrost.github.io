## 现状诊断

当前外观面板 4 个独立下拉（pattern×8 / colorway×33 / whiteLevel×4 / furLength×4），主要痛点：
- pattern 是抽象名词（"玳瑁"/"三花"/"重点色"），纯文字、无视觉线索，用户靠猜
- colorway 33 项里大部分被 hidden+disabled 藏起来，仍是个长列表
- pattern↔colorway↔whiteLevel 三者联动但无提示，改一个另两个被静默 normalize 后跳值，用户困惑
- 面板里**完全没有预览**，选完才知道长什么样
- 4 个 select 在移动端要逐个展开
- "换一只"是黑盒

## 核心思路

按你的三个选择：**Chip + swatch grid UI** + **面板顶部 mini live preview** + **扩展 5 个常见 colorway**。

### 契约约束（不能违反，已验证）

`tools/check-runtime.mjs` 里的硬断言：
- 9 个 element id 必须保留：`appearance-{toggle,panel,close,pattern,colorway,white-level,fur-length,randomize,reset}`
- HTML 里所有 `<option value="X" data-pattern="Y">` 的集合必须**完全等于** `COLORWAYS` 里所有 `${pattern}-${colorway}` 组合
- `normalize({})` 必须返回固定 default（`tabby/orange/low/short`）
- Escape 关闭面板后焦点必须回到 toggle
- `appearance-pattern.value='calico'; dispatch('change')` 后 colorway 必须自动 normalize 成 `'classic'`
- `COLORS/PATTERNS/FUR_LENGTHS` 的 keys 必须与 `shelter-cats/assets/data/enums.json` 完全对齐
- `.appearance-source` 必须有 `font-size: 0.6rem`、不能有 `opacity:`

渲染契约（Explore 已确认）：**新 colorway 在现有 pattern 下 = 纯数据改动，零渲染代码改动**。`resolvePalette()` 的 fallback 链保证任何 `base/accent/third/white` 组合都能产出合法 hex。

## 实施步骤

### 1. `appearance.js` — 加 5 个 colorway（纯数据）

全部用**现有 10 个 color token**，不动 PATTERNS，不动 COLORS，不引入新机制：

```js
bicolor: {
  // 现有 4 个...
  'blue-cream':       { base:'blue',     accent:'cream', white:'cream', colors:['blue','cream']     },
  'chocolate-cream':  { base:'chocolate',accent:'cream', white:'cream', colors:['chocolate','cream']},
  'lilac-white':      { base:'lilac',    accent:'white', white:'white', colors:['lilac','white']    },
},
tuxedo: {
  // 现有 1 个...
  'gray-white': { base:'gray', accent:'white', white:'white', colors:['gray','white'] },
  'blue-white': { base:'blue', accent:'white', white:'white', colors:['blue','white'] },
},
```

这些都是收容所真实能见到的配色变体。shelter enums.json **无需改动**（没新 color token，词表对齐断言自动通过）。

### 2. `index.html` — 面板重构

**保留**所有 9 个 id。**保留**所有现有 `<option>`（包括 5 个新 colorway 的 option，契约要求 HTML option 集合 = COLORWAYS 集合）。

把现有 `.appearance-fields`（4 个 select 容器）改成 sr-only（视觉隐藏但仍可被 check-runtime dispatch change），在面板里新增可视 UI：


**关键设计**：
- chip grid 是 `<div role="radiogroup">` + `<button role="radio" aria-checked>` —— 不是 `role="menu"`（被禁）
- 每个 chip 用一个**通用 mini SVG 图标**（不针对每只猫渲染，只是抽象 pattern 示意，比如 solid=实心圆、tabby=竖纹方块、bicolor=对角分块、tuxedo=胸口白斑、calico=三色块拼图、tortie=斑驳双色、pointed=四肢深色、smoke=渐变）
- colorway swatch 是 24×24 的真实色块拼图，用 base/accent/white 三色按 pattern 类型排列
- mini preview 是独立 canvas，画静态俯视猫（loaf 姿态朝上），用现有 `colors()` palette + 简化的 head+body+tail 路径，不画腿/动画。每次 `applyAppearance` 或主题切换时重绘（不需要 RAF）
- 4 个原 `<select>` 用 `.sr-only` 视觉隐藏，但保留 DOM + change 事件（check-runtime 测试用）

### 3. `cat-and-mouse.css` — 新 UI 样式

- `.appearance-preview` canvas：圆角、半透明背景、dpr 缩放
- `.appearance-chip-grid`：CSS grid，4 列，gap 8px
- `.appearance-chip`：方形按钮，36×36，内嵌 SVG 图标 + 下方文字；选中态用 `--accent-soft` 背景 + `--accent` 边框
- `.appearance-swatch-grid`：flex wrap，gap 6px
- `.appearance-swatch`：24×24 色块拼图按钮，圆角；选中态 ring
- `.appearance-segmented`：一行按钮，全宽，圆角连体；选中态高亮
- `.appearance-fields`（旧 select 容器）：`sr-only`（保留可访问性但不占视觉空间）
- 移动端（@media max-width:430px）：chip grid 改 3 列，swatch 缩小
- **保留** `.appearance-source` 的 `font-size: 0.6rem` 和无 `opacity` 约束

### 4. `app.js` — 新渲染 + 同步逻辑

新增函数（不破坏现有 contract）：
- `drawAppearancePreview(ctx)`：在 preview canvas 上画静态俯视猫。复用 `colors()` 调色板，画简化版 head（圆 + 两耳 + 鼻头）+ body（椭圆）+ tail（贝塞尔）。根据当前 appearance 的 pattern/whiteLevel/furLength 决定涂哪些斑块。
- `renderPatternChips()`：根据 `Appearance.PATTERNS` 渲染 8 个 chip，绑定 click → `applyAppearance({pattern})`
- `renderColorwaySwatches()`：根据 `Appearance.validColorways(pattern)` 动态生成 swatch，每个 swatch 用 inline SVG/Canvas 画三色拼图
- `renderWhiteLevelSegments()` / `renderFurLengthSegments()`：渲染 segmented control
- 扩展 `syncAppearanceControls()`：除了同步 4 个隐藏 select 的 value（保留现有逻辑给 check-runtime 用），还同步 chip/swatch/segment 的 `aria-checked` 和选中态 class，并触发 preview 重绘
- 在 `applyTheme` 和 `I18n.onChange` 里加 preview 重绘 + chip label 重新国际化

事件绑定：每个 chip/swatch/segment 的 click → `applyAppearance({...}, true)`。所有状态变更统一走 `applyAppearance`，select 和可视 UI 两边都同步。

### 5. `i18n.js` — 加标签

- 5 个新 colorway 标签（`colorwayBlueCream` 等）
- 新 UI 元素的 aria-label：`appearancePreviewAria`、`appearancePatternGroupAria`、`appearanceColorwayGroupAria` 等
- pattern chip 标签复用现有 `patternSolid`/`patternTabby` 等

### 6. `tools/check-runtime.mjs` — 加新 id 和断言

- `ids` 数组加：`appearance-preview`, `appearance-pattern-grid`, `appearance-colorway-grid`, `appearance-white-level-group`, `appearance-fur-length-group`
- 加断言：
  - HTML 里有 `<canvas id="appearance-preview"`
  - HTML 里有 `role="radiogroup"` 的 pattern 容器
  - chip 数量 = `Object.keys(PATTERNS).length`
  - 点 pattern chip 后 `getSnapshot().appearance.pattern` 更新（与现有 select 测试并行）
  - 5 个新 colorway 同时出现在 COLORWAYS 和 HTML option 里
- **保留**所有现有 appearance 相关断言不动（id 集合、normalize default、tortie whiteLevel、escape 焦点归还、`.appearance-source` 样式约束等）

### 7. `tools/visual-harness.html` — 扩 appearanceSheet

`__appearanceSheet` 的 recipes 数组从 8 个代表色扩到包含 5 个新 colorway（作为 sheet 末尾的"新配色展示"行），让 contact sheet 覆盖扩展。`__furSheet` 不变。

### 8. 跑 build.py + 手动验证

- `python3 tools/build.py`：必须通过（自动重算 `?v=` hash 并刷新所有 stamp + 跑 check-gait + check-runtime）
- 手动浏览器验证：preview 实时跟随、chip 切换、swatch 刷新、segmented 切换、escape 关闭、中英切换、深色模式、移动端 320px 可用

## 我做的几个判断（你可以在 plan 审查时推翻）

1. **不加新 pattern**：新 pattern 需要新渲染分支（paintTailCoat/paintBodyCoat/paintHeadCoat/limbCoatColor 都要加 case），工程量明显更大且高视觉风险。本次只做 colorway 扩展（纯数据）。如果你想要 torbie/tortie-point 这种新 pattern，我建议另起一次。
2. **5 个新 colorway 全部是 bicolor/tuxedo 配色变体**：因为这两类最常见且纯数据。tabby/solid/calico/tortie/pointed/smoke 现有覆盖已经够好。
3. **mini preview 是静态俯视猫**（不动画）：节省 CPU，"识别图"足够直观。如果你想要呼吸/眨眼，告诉我，加上不难。
4. **保留 4 个 select 作为隐藏状态持有者**：这是最低风险路径——check-runtime 的所有现有断言天然成立。完全删 select 会让契约更新工作量翻倍且收益小。
5. **chip 图标用通用 SVG 抽象示意**（不是逐猫渲染）：8 种 pattern 各一个固定图标，简洁一致。如果你想要 chip 内嵌真实 mini canvas 逐猫渲染（最直观但实现量大），告诉我。
